# 📚 ИНСТРУКЦИЯ по запуску Telegram-магазина на Windows
### Для тех, кто никогда не программировал — написано простым языком

> Представьте, что этот проект — это **готовая книга с рецептами** (магазин).
> Ваша задача — просто открыть нужную программу (Python), вставить ингредиенты (настройки в `.env`), и нажать «Готовить» (запустить бота).
> Весь остальной код уже написан за вас.

---

## 📋 ЧАСТЬ 1: Проверка и установка Python

### Шаг 1 — Проверяем, есть ли Python

Нажмите `Win + R`, введите `cmd`, нажмите Enter.
В открывшемся чёрном окне (терминал) напишите:

\`\`\`cmd
python --version
\`\`\`

**Что должно появиться:**
\`\`\`
Python 3.11.x  (или 3.10, 3.12 — любая версия от 3.10)
\`\`\`

**Если вместо этого написано `python не является внутренней командой`** — Python не установлен.
Зайдите на сайт **https://www.python.org/downloads/** и скачайте версию Python 3.11.
⚠️ **Важно при установке**: поставьте галочку `☑ Add Python to PATH` — без неё ничего не заработает.

После установки закройте терминал и откройте заново, повторите команду `python --version`.

### Шаг 2 — Переходим в папку с проектом

В терминале введите (замените путь на свой):

\`\`\`cmd
cd C:\Users\ВашеИмя\Projects\tg_bot_for_ai_sofi
\`\`\`

**Как проверить, что вы в нужной папке:**
Введите `dir` — должны появиться файлы `bot.py`, `.env`, `requirements.txt` и папки `shopbot`, `docs`, `scripts`.

### Шаг 3 — Создаём виртуальное окружение

> **Аналогия из филологии:** Виртуальное окружение — это как **отдельная тетрадь для каждого предмета**.
> Вы не смешиваете конспекты по лингвистике с конспектами по литературе.
> Так и Python: для каждого проекта — своя изолированная папка с библиотеками.

\`\`\`cmd
python -m venv .venv
\`\`\`

Команда создаст папку `.venv` — можете убедиться в проводнике.

\`\`\`cmd

\`\`\`

**Как понять, что сработало:**
В начале строки терминала появится `(.venv)`:
\`\`\`

\`\`\`powershell

\`\`\`
Если и там ошибка — выполните один раз:
\`\`\`powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
\`\`\`

### Шаг 5 — Устанавливаем зависимости (библиотеки)

> **Аналогия:** Зависимости — это как **список книг по программе курса**.
> Прежде чем писать реферат, вы читаете нужные источники.
> Здесь Python скачивает все нужные инструменты, чтобы бот умел работать с Telegram.

\`\`\`

Подождите пока установится (1–2 минуты). В конце должно быть `Successfully installed ...`

## 📋 ЧАСТЬ 2: Настройка конфигурации (.env)

Откройте файл `.env` в любом текстовом редакторе (можно Блокнот или VS Code):

\`\`\`
TELEGRAM_BOT_TOKEN=8676556825:AAFxXuYD9iD5...   ← токен вашего бота от @BotFather
ADMIN_IDS=688585894                               ← ваш Telegram ID (узнать у @userinfobot)
ADMIN_PASSWORD=best_team                          ← пароль для входа в админку
CURRENCY=UZS                                      ← валюта (можно UZS, USD, RUB и т.д.)
CHANNEL_ID=-1003045496764                         ← ID вашего Telegram-канала/группы
AUTO_DELETE_OUT_OF_STOCK_DAYS=7                   ← через сколько дней удалять товары не в наличии
\`\`\`

**Что можно менять, не боясь что-то сломать:**
- `ADMIN_PASSWORD` — придумайте свой пароль
- `CURRENCY` — поменяйте на нужную валюту
- `AUTO_DELETE_OUT_OF_STOCK_DAYS` — поставьте 14, 30 или любое число

**Что нельзя трогать без причины:**
- `TELEGRAM_BOT_TOKEN` — это уникальный ключ к боту, не делитесь им с посторонними

## 📁 ЧАСТЬ 6: Что за что отвечает — каждый файл

> **Аналогия из филологии:** Весь проект — это как **научный журнал**.
> Каждый файл — отдельная рубрика. Главный редактор — `bot.py`.
> Словарь терминов — `locales.json`. Архив статей — `shop.sqlite3`.

---

### 📄 `bot.py` (в корне) — Главный запускной файл

Это «рубильник» всего проекта. Одна строка: "запустить".
Сам по себе ничего не делает — просто говорит: "запускай основной модуль".
Аналогия: это как титульная страница книги — она отсылает к тексту внутри.

---

### 📄 `.env` — Файл с секретными настройками

Здесь хранятся все персональные данные: токен бота, пароль, ID канала.
Файл намеренно не загружается в интернет (он в .gitignore).
Аналогия: это ваша записная книжка с паролями — не для чужих глаз.
Меняйте смело, но никому не показывайте.

---

### 📄 `requirements.txt` — Список нужных библиотек

Перечисляет все внешние инструменты: pyTelegramBotAPI, python-dotenv и т.д.
Команда `pip install -r requirements.txt` читает этот список и устанавливает всё.
Аналогия: это как список литературы в конце дипломной работы —
без этих источников диплом не написать.

---

### 📄 `shop.sqlite3` — База данных (хранилище)

Это файл-таблица, где хранятся товары, заказы, корзины и данные пользователей.
Работает как Excel, но невидима — управляется автоматически через код.
Аналогия: картотека в библиотеке — каждая карточка знает где какая книга и кто её взял.
Если удалить этот файл — все товары и заказы пропадут.

---

### 📄 `bot.log` — Журнал событий

Каждое действие в боте записывается сюда: кто зашёл, что купил, какая ошибка.
Это как вахтёрский журнал: "10:35 - студент Иванов вошёл, 10:42 - вышел".
При ошибке — загляните сюда в первую очередь.
Файл не удаляйте, он нужен для диагностики.

---

### 📂 `shopbot/` — Главная папка с кодом магазина

#### `shopbot/config.py` — Настройки и логирование

Читает ваш файл .env и раздаёт настройки всем остальным частям программы.
Если TOKEN не указан — бот откажется запускаться с понятной ошибкой.
Аналогия: это секретарь деканата — все документы проходят через него,
и он знает все правила и пароли.

#### `shopbot/bot.py` — Логика работы бота с покупателями

Здесь описано: что бот делает когда покупатель пишет /start, добавляет товар в корзину,
оформляет заказ, ищет товар. Это основной "мозг" для обычного пользователя.
Аналогия: это скрипт консультанта в магазине — как отвечать на каждый вопрос покупателя,
что делать если товара нет в наличии, как принять заказ.

#### `shopbot/admin.py` — Панель администратора

Весь функционал для владельца магазина: добавить товар, изменить цену,
посмотреть заказы, поменять статус.
Аналогия: это должностная инструкция директора магазина —
что и в каком порядке он имеет право делать.

#### `shopbot/db.py` — Работа с базой данных

Создаёт таблицы в базе данных при первом запуске, описывает структуру хранения.
Все таблицы: категории, товары, корзины, заказы, настройки пользователей.
Аналогия: это план картотеки — какие ящики есть, что в каждом хранится,
как карточки связаны между собой.

#### `shopbot/i18n.py` — Многоязычность (ru / uz / en)

Загружает тексты из locales.json и переводит их на нужный язык пользователя.
Каждый покупатель может выбрать язык — бот запомнит это в базе.
Аналогия: это синхронный переводчик — слушает русский запрос,
отвечает на узбекском или английском, смотря что нужно клиенту.

#### `shopbot/keyboards.py` — Кнопки в боте

Описывает все кнопки (меню, корзина, категории, инлайн-кнопки под товарами).
Когда покупатель видит "🛒 Магазин" или "➕ В корзину" — это отсюда.
Аналогия: это дизайн-макет интерфейса — расположение кнопок в меню,
как они называются и что происходит при нажатии.

#### `shopbot/channel.py` — Публикация в Telegram-канал

Когда добавляете товар в админке и нажимаете "Опубликовать в канал" —
этот файл отправляет карточку с фото в ваш Telegram-канал.
Аналогия: это отдел маркетинга — берёт карточку товара из склада
и публикует красивое объявление в социальных сетях магазина.

---

### ⭐ `shopbot/locales.json` — Все тексты бота на 3 языках

**ВОТ ЧТО МОЖНО СМЕЛО МЕНЯТЬ!**

Здесь хранятся все фразы, которые бот говорит пользователю.
Три секции: `"ru"` (русский), `"uz"` (узбекский), `"en"` (английский).

**Пример — что найдёте внутри:**
\`\`\`json
"ru": {
    "start_customer": "👋 Добро пожаловать в наш магазин!",
    "cart_empty": "🧺 Ваша корзина пуста.",
    "order_placed": "✅ Заказ #{id} оформлен! Итого: {total}"
}
\`\`\`

**Что можно изменить:**
- Приветственное сообщение (`start_customer`) — напишите своё
- Текст кнопок и подсказок — адаптируйте под стиль вашего бренда
- Добавить смайлики или убрать — по желанию

**Что нельзя менять:**
- Названия ключей (слова до `:`) — только тексты после них
- Переменные в фигурных скобках: `{id}`, `{total}`, `{name}` — их не трогать
- Структуру файла — все три языка (`ru`, `uz`, `en`) должны оставаться

## 🔧 ЧАСТЬ 7: Разбор главных функций (что и зачем)

### Функция `start` — приветствие при /start

Срабатывает когда любой пользователь впервые написал боту /start.
Отображает главное меню с кнопками: Магазин, Корзина, Поиск, Мои заказы.
Если в ссылке есть специальный код (order_XXXX) — открывает конкретный товар.
**Аналогия:** консультант у входа в магазин — встречает каждого покупателя и показывает меню.

---

### Функция `send_product` — показ карточки товара

Отправляет покупателю красивую карточку товара: фото, название, описание, цена.
Если у товара одно фото — отправляет как одиночную картинку.
Если фотографий несколько (до 5) — отправляет альбомом.
**Аналогия:** витрина магазина — каждый товар имеет свой красивый ценник и фото.

---

### Функция `show_categories` — список категорий

Запрашивает из базы все категории и показывает их покупателю в виде кнопок.
Рядом с каждой категорией показывает сколько товаров в ней доступно.
Если магазин пуст — говорит об этом вежливым сообщением.
**Аналогия:** содержание каталога — "Платья (12 моделей)", "Сумки (7 моделей)".

---

### Функция `show_category_page` — просмотр товаров с пролистыванием

Показывает товары одной категории по одному, с кнопками "◀ Назад" и "▶ Вперёд".
Покупатель листает как страницы книги — видит карточку каждого товара по очереди.
Кнопки "В корзину" и "Купить сейчас" — прямо под каждым товаром.
**Аналогия:** перелистывание страниц каталога — плавно, один товар за раз.

---

### Функция `show_cart` — содержимое корзины

Показывает все товары в корзине пользователя с количеством и ценой каждого.
Внизу показывает итоговую сумму и кнопку "Оформить заказ".
Считает итог автоматически, пересчитывает при любом изменении.
**Аналогия:** чек на кассе — перечень покупок с суммой к оплате.

---

### Функция `handle_checkout_input` — оформление заказа

Проводит покупателя через 3 шага: имя → номер телефона → адрес доставки.
Умеет принимать номер телефона через кнопку "Поделиться контактом" или вручную.
После получения всех данных — автоматически создаёт заказ и уведомляет администратора.
**Аналогия:** анкета при покупке в интернет-магазине — заполняете по шагам, без лишних полей.

---

### Функция `create_order` — создание заказа в базе

Сохраняет заказ в базу данных: имя клиента, телефон, адрес, состав заказа, итоговая сумма.
После сохранения — очищает корзину покупателя и отправляет уведомление всем администраторам.
Каждому заказу присваивается уникальный номер (#ID).
**Аналогия:** складской журнал — запись нового заказа с отметкой "принято, уведомили кладовщика".

---

### Функция `search_command` — поиск товаров

Ищет товары по названию и описанию — регистр не важен (большие/маленькие буквы).
Показывает до 20 результатов, если совпадений много.
Если ничего не нашли — сообщает вежливым текстом.
**Аналогия:** поисковая строка в Google — вводишь "синее платье", находит всё подходящее.

---

### Функция `translate` — переводы и тексты

Берёт ключ (например "cart_empty") и возвращает текст на языке пользователя.
Запоминает язык каждого пользователя — не спрашивает повторно.
Все тексты бота идут именно через эту функцию.
**Аналогия:** синхронный переводчик на конференции — слышит ключевое слово, переводит нужному.

---

### Функция `verify_admin_password` — проверка пароля

Проверяет введённый пароль безопасным способом (защита от угадывания по времени).
Дополнительно проверяет: точно ли этот пользователь в списке администраторов.
Если пароль неверный — доступ к панели не открывается, ошибка записывается в лог.
**Аналогия:** вахтёр со списком допуска — даже если знаешь пароль, но не в списке — не пустит.

---

### Функция `money` — форматирование цен

Превращает число вроде 150000 в красивую строку "150,000.00 UZS".
Используется везде где показывается цена — в карточках товаров, корзине, заказах.
Берёт валюту из настроек .env — достаточно поменять CURRENCY=USD и везде появится доллар.
**Аналогия:** кассовый аппарат — любая сумма распечатывается в стандартном формате чека.

---

### Функция `initialize_database` — создание таблиц

При первом запуске создаёт все нужные таблицы в базе данных.
При повторных запусках — ничего лишнего не делает, просто проверяет что всё на месте.
Умная: если обновить код бота с новыми полями — добавит их без потери старых данных.
**Аналогия:** подготовка новой тетради — провести строчки, подписать разделы, разметить страницы.

## 🚨 ЧАСТЬ 8: Список ошибок и что они означают

### ❌ `Set TELEGRAM_BOT_TOKEN in the .env file before starting the bot.`

Что случилось: в файле .env не указан или пустой TELEGRAM_BOT_TOKEN.
Что делать: откройте .env, проверьте строку TELEGRAM_BOT_TOKEN=ВАШ_ТОКЕН.
Токен берётся у @BotFather в Telegram → /mybots → Выбрать бота → API Token.
Бояться не нужно — просто скопируйте токен правильно, без лишних пробелов.

---

### ❌ `Set at least one numeric Telegram user ID in ADMIN_IDS in the .env file.`

Что случилось: в ADMIN_IDS стоит пустое значение или не число.
Что делать: найдите свой Telegram ID — напишите боту @userinfobot команду /start.
Он ответит вашим числовым ID (например: 688585894). Вставьте его в ADMIN_IDS.
Буквы (@username) там не работают — только цифры.

---

### ❌ `Could not notify admin ... about order ...`

Что случилось: покупатель сделал заказ, но уведомление администратору не дошло.
Скорее всего причина: администратор не написал боту /start хотя бы раз.
Что делать: найдите своего бота в Telegram, напишите ему /start — и всё заработает.
Заказ при этом всё равно сохранился в базе — ничего не потеряно.

---

### ❌ `Locale locales.json must define exactly: ['en', 'ru', 'uz']`

Что случилось: вы редактировали locales.json и случайно удалили секцию языка.
Что делать: откройте locales.json, убедитесь что там три раздела: "ru", "uz", "en".
Не удаляйте ключи — только меняйте тексты внутри кавычек после двоеточия.
Если запутались — восстановите файл из резервной копии или через git.

---

### ❌ `Locale ... has incompatible format fields for ...`

Что случилось: вы редактировали текст в locales.json и удалили или переименовали {переменную}.
Например, написали "Заказ номер #ID" вместо "Заказ #{id}" — убрали фигурные скобки.
Что делать: верните фигурные скобки точно как было: {id}, {total}, {name}, {price} и т.д.
Переменные внутри {} — это не текст, это код. Их содержимое трогать нельзя.

---

### ❌ `Fatal error in bot infinity_polling` (с трассировкой ошибки ниже)

Что случилось: бот столкнулся с неожиданной ошибкой и остановился.
Что делать: прочитайте строки ниже этой ошибки в логе — там написано что именно случилось.
Чаще всего причина: нет интернета, неверный токен, или Telegram временно недоступен.
Попробуйте запустить бота снова командой: python bot.py

---

### ❌ `python не является внутренней или внешней командой` (в cmd)

Что случилось: Python не установлен или не добавлен в PATH.
Что делать: переустановите Python с сайта python.org, обязательно поставив галочку "Add to PATH".
После установки обязательно закройте и откройте терминал заново.
Это самая частая ошибка у новичков — не пугайтесь, решается за 5 минут.

---

### ⚠️ `Could not process callback ... from user ...`

Что случилось: пользователь нажал кнопку, и произошла ошибка при обработке.
Пользователь увидит сообщение "Произошла ошибка, попробуйте ещё раз".
Бот при этом продолжит работу — это не критично, бот не падает.
Подробности смотрите в bot.log — там будет полный текст ошибки.
